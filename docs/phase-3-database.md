## Prisma Version Note

The current Prisma CLI used during validation was Prisma 7.8.0. Prisma 7 moves the connection URL out of `schema.prisma` and into `prisma.config.ts`, so the datasource in the schema contains only:

```prisma
datasource db {
  provider = "postgresql"
}
```

Runtime database access uses `@prisma/adapter-pg` through `lib/db/prisma.ts`.

- Target industries from the original brief

No admin password is seeded. Credentials authentication will be implemented in Phase 4 with secure hashing and an explicit setup flow.

## Migration Workflow

Install dependencies when ready:

```bash
pnpm install
```

Validate and format:

```bash
pnpm db:validate
pnpm db:format
pnpm db:generate
```

Apply the generated migration locally:

```bash
pnpm db:migrate
```

Seed local data:

```bash
pnpm db:seed
```

Deploy production migrations:

```bash
pnpm db:deploy
```

The generated migration SQL has not been applied because no PostgreSQL database connection was provided in this phase.

## Security Decisions

- All primary entities use generated IDs rather than sequential public IDs.
- Lead records expose a separate `publicId`.
- Role permissions are centralized on `Role`.
- Admin changes can be captured through `AuditLog`.
- Auth.js-compatible account, session, and verification-token tables are ready for Phase 4.
- Contact and quote records store consent, IP address, user agent, assignment, and status for auditability.
- No secrets, passwords, API keys, or database credentials are committed.

## Performance Decisions

- Slugs and key lookup fields are unique.
- Admin workflow filters have indexes on status, featured flags, assignment, and creation time.
- Join tables use composite primary keys.
- Product catalog pages can query categories, products, industries, images, specs, downloads, and FAQs efficiently.
- Public pages can be statically cached later while admin and lead workflows remain dynamic.
